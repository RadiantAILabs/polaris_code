# Instructions for a SymPy issue fix

Work only with the SymPy checkout already installed at `/testbed`. Do not download or install another SymPy copy, fetch its GitHub repository or PR diffs, or fetch SymPy files from PyPI. Installing a missing third-party dependency is allowed. Use the local tree to check version-specific behavior.

1. **Reproduce the public failure before editing.** In `/testbed`, run a short `run_python` script with explicit imports, the reported call and an assertion for the expected behavior. Keep the failing script as a post-patch check if supported. Run one nearby contrast: direct/nested, default/option, concrete/symbolic, or evaluated/`evaluate(False)`. For mathematical claims use exact small values, substitution or an independent identity; for expression form inspect `srepr`/`args`; for a printer assert the exact string only if output text is the contract. Do not replace a desired expectation with today's result merely to make a test pass ([PR 23499](https://github.com/sympy/sympy/pull/23499)). Statements name a reproducible operation; reviewers request reported-case and independent-value tests ([PR 24030](https://github.com/sympy/sympy/pull/24030), [PR 24293](https://github.com/sympy/sympy/pull/24293)).

2. **Trace the dispatch from the named API to the owning layer.** Search the public name and read its implementation plus nearby tests, then follow calls inward and values outward. For construction/evaluation search `__new__`, `eval`, `_eval_evalf` and `_eval_is_<fact>`; the assumptions engine tries class handlers before inferred facts (`sympy/core/assumptions.py:489-511,575-595`). For printing search the requested target's printer: dispatch tries an object hook (`_latex`/`_sympystr`), then `_print_<Class>` along the class hierarchy, then fallback (`sympy/printing/printer.py:16-72,294-338`). For parsing distinguish `sympify` → `parse_expr` from `parse_latex` → ANTLR tree conversion (`sympy/core/sympify.py:490-499`; `sympy/parsing/latex/__init__.py:30-35`; `sympy/parsing/latex/_parse_latex_antlr.py:61-95`). A missing ANTLR dependency is not a code-behavior failure (`doc/src/modules/parsing.rst:104-114`).

3. **Search below public wrappers when needed.** In `polys`, the public `Poly`/`factor` layer, internal `DMP`/`dmp_`/`dup_` routines, `PolyRing`/`PolyElement` and coefficient domains are separate (`doc/src/modules/polys/internals.rst:7-43,48-61`; `sympy/polys/rings.py:196,556,618-626`). Matrix normal-form wrappers delegate to `sympy.polys.matrices.normalforms` (`sympy/matrices/normalforms.py:3-24,123-127`; `sympy/polys/matrices/normalforms.py:177,339`). In units, an SI instance can inherit behavior from `UnitSystem`, with `DimensionSystem` handling dimensionless checks (SymPy 1.12: `sympy/physics/units/unitsystem.py:152-199`; `sympy/physics/units/dimensions.py:463-471`). Other starting packages include `concrete/` for sums/products, `simplify/`, `physics/`, `combinatorics/`, `geometry/`, `codegen/` and `utilities/`; check the task version's tree before assuming a path ([maintainer discussion](https://groups.google.com/g/sympy/c/eWar-577cKI)). Search the producer, consumer and sibling variants before editing a shared hook. Reviewers have moved hooks to the owning class and found downstream regressions ([PR 24133](https://github.com/sympy/sympy/pull/24133), [PR 23693](https://github.com/sympy/sympy/pull/23693)).

4. **Preserve symbolic contracts.** For a `Basic` subclass with nonempty `args`, check `expr == expr.func(*expr.args)` (`doc/src/tutorial/manipulation.rst:351-424`). For assumptions, `None` means unknown; never coerce it to `False` with an unguarded truth test. Use `is True`/`is False` or `fuzzy_and`/`fuzzy_or`/`fuzzy_not` (`doc/src/guides/assumptions.rst:100-175`; `doc/src/guides/booleans.rst:145-195,245-279`). For numeric hooks, note `_eval_evalf` receives **binary** precision, unlike public decimal `evalf` ([custom-functions guide](https://docs.sympy.org/latest/guides/custom-functions.html)). Check zero, symbolic, complex, unevaluated and nested forms when relevant. A numerically plausible result may still be wrong on a branch or domain ([PR 23583](https://github.com/sympy/sympy/pull/23583)).

5. **Fix the smallest owning layer, then cover the public behavior.** Add a regression in nearby `sympy/**/tests/test_*.py`; the test file often matches the source module ([writing-tests guide](https://docs.sympy.org/latest/contributing/new-contributors-guide/writing-tests.html)). Test the reported case and one contrasting boundary. Keep existing tests unless their expectation is demonstrably wrong. Assert exact form when form affects semantics, performance or the printer contract; otherwise check mathematical equality or an invariant. Reviewers have requested sibling rewrites, downstream callers, exact rational inputs and explicit expected forms ([PR 22993](https://github.com/sympy/sympy/pull/22993), [PR 22476](https://github.com/sympy/sympy/pull/22476), [PR 24401](https://github.com/sympy/sympy/pull/24401), [PR 23171](https://github.com/sympy/sympy/pull/23171)). Search same-named hooks and related modes; decide which are genuinely affected. Do not weaken unrelated behavior or change an API signature to satisfy one case.

6. **Verify with the available commands.** The container is at `/testbed`, with SymPy installed; command policy allows `python *` and `pytest *`. For a shell-capable gate, run `python bin/test test_basic` or `pytest -q sympy/core/tests/test_basic.py -k test_name`, then related modules. For doctests run `python bin/doctest sympy/core/basic.py`; for quality run `python bin/test quality`. With only `run_python`, use `assert sympy.test('test_basic') == 0` or `assert sympy.doctest('sympy/core/basic.py')`; unchecked returns hide failure (`sympy/__init__.py:243`; `sympy/testing/runtests.py:568-569,572-605,625-642`). Keep runs narrow, classify missing dependencies separately, and report exactly what ran. `make html` requires extra dependencies and is outside the command allowlist (`doc/src/guides/contributing/build-docs.rst:8-35,121-137`).

7. **Review compatibility and user-facing details.** Preserve supported arguments, keyword names, return types, error behavior and default printer output unless a public change is justified. SymPy prefers compatible designs and deprecates necessary public breaks; correcting mathematically wrong behavior is normally a bug fix (`doc/src/guides/contributing/deprecations.md:23-65,67-113`). Update public docstrings/examples, run affected doctests, and describe user-visible changes in release notes if preparing a PR ([workflow guide](https://docs.sympy.org/latest/contributing/new-contributors-guide/workflow-process.html)). State which behavior and tests were checked and what remains uncertain.
